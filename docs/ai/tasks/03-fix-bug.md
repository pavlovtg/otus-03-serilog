# Исправление бага по описанию

## Контекст

Задача — воспроизвести баг через failing-тест, исправить его, убедиться что тест зелёный.

Правила проекта:

- Подход TDD: сначала пишется failing-тест, потом вносится фикс.
- Тесты зеркалируют структуру `src/`: класс `src/Serilog/Core/Foo.cs` → тест `test/Serilog.Tests/Core/FooTests.cs`.
- Агент определяет путь к тест-файлу автоматически по правилу зеркальной структуры.
- После фикса запускается весь тестовый suite (`dotnet test`), а не только тесты конкретного класса.
- Агент записывает код напрямую в файлы, не показывает в чате.

Как применять: укажи класс, namespace и описание бага в промпте ниже.

## Пример промпта

```
Исправь баг в классе {Namespace.ClassName}.

Описание бага: {описание воспроизведения и ожидаемого поведения}

Требования:
- Прочитай исходный файл класса и связанные типы.
- Определи путь к тест-файлу по правилу зеркальной структуры src/ → test/Serilog.Tests/.
- Напиши failing-тест, воспроизводящий баг, запиши его в тест-файл.
- Убедись, что тест падает (dotnet test — ожидаемое падение).
- Внеси минимальный фикс в исходный файл класса.
- Запусти dotnet test и убедись, что все тесты зелёные.
- Код записывай напрямую в файлы, в чате не показывай.
```

## Критерии готовности

- Failing-тест написан и воспроизводит баг до фикса.
- Фикс внесён в исходный файл класса.
- `dotnet test` завершается без ошибок и падений.
- Новый тест зелёный, остальные тесты не сломаны.
