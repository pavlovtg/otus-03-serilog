# Создать файлы с описанием типовых задач

## Роль

- Ты — разработчик, подготавливающий репозиторий для работы с AI-ассистентом Cline.

## Контекст

- Проект — форк serilog/serilog, учебное ДЗ по добавлению AI-инструкций (`.clinerules`).
- Разработка ведётся на C#.
- Разработка ведётся по TDD, покрытие тестами не менее 80%.
- Тесты зеркалируют структуру `src/`: класс `src/Serilog/Core/Foo.cs` → тест `test/Serilog.Tests/Core/FooTests.cs`.
- Тестовый проект называется `<Проект>.Tests` (например, `Serilog.Tests`).
- Тестовый фреймворк — xUnit, mock-фреймворки не используются.

## Задача

Создать шаблоны для типовых задач:

1. Покрытие модуля тестами — написать unit-тесты для существующего класса по паттернам проекта.
2. Рефакторинг без изменения поведения — привести существующий код к актуальному code style без изменения логики.
3. Исправление бага по описанию — воспроизвести баг через failing-тест, исправить, убедиться что тест зелёный.

## Требования

- Сценарии описать в отдельных файлах в папке `docs/tasks/`.
- Формат описания — Markdown.
- Оптимизировать под Cline и Claude Sonnet.
- Структура каждого файла: **Контекст** / **Пример промпта** / **Критерии готовности**.
- В разделе **Контекст**: описание задачи и инструкция по применению (без плейсхолдеров).
- В разделе **Пример промпта**: плейсхолдеры для конкретики + ожидаемый формат ответа внутри промпта.
- Путь к тестовому файлу агент определяет автоматически по правилу зеркальной структуры — не указывать как плейсхолдер.
- Агент записывает готовый код напрямую в файл, не показывает в чате.
- При рефакторинге и исправлении бага — запускать весь тестовый suite (`dotnet test`), а не только тесты конкретного класса.
